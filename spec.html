§0. プロジェクト概要

xxd 形式の16進ダンプと Nekono's Base32 (ひらがな32文字 + 大字パディング) との間を双方向変換する単一ファイルの静的Webページを作る。ビルドステップなし、index.html 1枚で完結。ブラウザにD&Dまたはコピペで動く。

§1. 符号化仕様 (Encoding Spec)

§1.1 アルファベット表

5ビット → ひらがな1文字。OCR誤認・毛筆判読性を考慮して以下32文字を採用 (除外したものについては §1.4 参照)。

値字値字値字値字
0あ8け16ち24ふ
1い9こ17て25ま
2う10さ18と26み
3え11し19な27む
4お12す20に28も
5か13せ21の29や
6き14そ22は30ゆ
7く15た23ひ31よ

§1.2 パディング

末尾不足ビットの埋め草には 句点「。」 を使用。RFC 4648 と同じく、入力バイト長 mod 5 によって以下のパディング数:

入力バイト出力文字パディング
126
244
353
471
580

§1.3 区切り文字

可読性のため、出力時は 4文字ごとに中黒「・」 を挿入する。デコード時は無視。

例: けせちひけ。。。 → けせち・ひけ。。・。

…と思ったが、4字区切りだとパディングがブロック境界で分断されて見苦しい。8文字ごとに改行 + 4文字ごとに「・」 を推奨。

こいにち・けせちひ
けお。。・。。。。

§1.4 除外文字とその理由

§2. デコーダ寛容性 (Lenient Decoder)

Crockford Base32 の精神に倣う。生成は厳格・受理は寛容 の原則。

§2.1 カタカナ→ひらがな自動マッピング

入力中の以下のカタカナは、対応するひらがなとして受理する:

ア→あ イ→い ウ→う エ→え オ→お
カ→か キ→き ク→く ケ→け コ→こ
サ→さ シ→し ス→す セ→せ ソ→そ
タ→た チ→ち テ→て ト→と
ナ→な ニ→に ノ→の
ハ→は ヒ→ひ フ→ふ
マ→ま ミ→み ム→む モ→も
ヤ→や ユ→ゆ ヨ→よ

§2.2 OCR救済マッピング (debatable)

警告を出した上で以下を受理:

ツ → し  (シ/ツ判別困難への救済)
ヘ → ふ  (本来 へ だが本符号外なので最寄りへフォールバック)

§2.3 完全に無視する文字

  • ASCII空白 (スペース・タブ・改行)
  • 全角スペース
  • 中黒「・」
  • 読点「、」(誤入力救済)

§2.4 拒絶する文字

§1.4 の除外字 (つ ぬ ね め れ わ る ろ ほ へ を ん) と、対応マッピングのないカタカナ (ヌ ネ リ ル レ ロ メ など) は デコードエラー とし、位置と文字を明示してUI上でハイライト。

§2.5 パディング検証

末尾の「。」の数が §1.2 の表と矛盾する場合はエラー。ただし --lenient モードでは末尾「。」の過不足を黙って補正してもよい (UIのトグルで切替)。

§3. xxd 形式

§3.1 既定形式 (xxd default)

00000000: 4865 6c6c 6f2c 2057 6f72 6c64 210a       Hello, World!.
  • 先頭: 16進オフセット8桁 + :
  • 中央: 2バイト (4hex) ごとにスペース、最大16バイト/行
  • 右側: ASCII表現 (非印字は .)。パース時は無視。

§3.2 plain hex 形式 (xxd -p)

48656c6c6f2c20576f726c64210a

連続した16進文字列。行折り返しあり。

§3.3 パーサ動作

  • 両形式を自動判定 (: の有無で判別)
  • 16進以外の文字は黙ってスキップ (xxd -r 互換)
  • 奇数桁で終わった場合はエラー

§4.1 ラウンドトリップテスト

xxd → Nekono32 → xxd および Nekono32 → xxd → Nekono32 が恒等関数になることを単体テストで確認すること (テストハーネスは別ファイル test.html に作ってもよい)。

§4.2 ファズテスト

ランダム生成した1〜1024バイトのバイナリ1000本でラウンドトリップが完全一致することを確認。

§5. UI 要件

§5.1 レイアウト

縦2ペイン (モバイル) / 横2ペイン (デスクトップ、768px以上)。中央に変換方向ボタン。

┌──────────────────────┐  ┌──────────────────────┐
│  xxd / hex           │  │  Nekono's Base32     │
│  ┌────────────────┐  │  │  ┌────────────────┐  │
│  │                │  │⇄ │  │                │  │
│  │  (textarea)    │  │  │  │  (textarea)    │  │
│  │                │  │  │  │                │  │
│  └────────────────┘  │  │  └────────────────┘  │
│  [copy] [clear]      │  │  [copy] [clear]      │
└──────────────────────┘  └──────────────────────┘

§5.2 機能要件

  • リアルタイム変換: 片方を編集するともう片方が即座に更新 (debounce 100ms)
  • 方向ボタン: 中央の「⇄」で「どちらが入力ソースか」をトグル。ソース側だけが編集可、もう一方は読み取り専用。
  • コピーボタン: 各ペイン下にクリップボードコピー
  • エラー表示: パース失敗時、エラー位置の文字を赤背景でハイライトし、下部にメッセージ表示
  • lenient モードトグル: チェックボックス。OFF だと §2.2 のカタカナ救済とパディング補正を行わない
  • サンプル読み込み: 「例文を入れる」ボタン。テストベクトルからランダム1本ロード
  • 文字数カウンタ: 各ペインに「N文字 / Mバイト / 内容証明520字制限まであと…」を表示。520字を超えたら警告。
  • ダウンロード: Nekono32 側に「.txt でダウンロード」ボタン。縦書きCSS適用版もオプションで。

§5.3 デザイン方針

  • 和風 (内容証明っぽい雰囲気)。背景はオフホワイト、本文はセリフ系日本語フォント (Noto Serif JP 等)。
  • ダークモード対応 (prefers-color-scheme)。
  • 縦書きプレビューモード (writing-mode: vertical-rl) を切替で。これで内容証明の見本になる。
  • フォントサイズはユーザ調整可 (毛筆派閥向け)。

§5.4 アクセシビリティ

  • すべてキーボード操作可能。
  • 変換結果は aria-live="polite" で読み上げ対応 (ただし32音の読み上げは聞いてる方が辛いので、トグルでOFFに)。

§6. 技術スタック

  • HTML + CSS + Vanilla JS のみ。フレームワーク禁止。ビルド禁止。
  • ES2022 (top-level await可)。Bun/Node等不要。open index.html で動くこと。
  • Windows非依存。改行コードは LF。
  • 単一ファイル index.html 推奨。CSSとJSはインライン or <script type="module"> で別ファイル分割は可。
  • 文字コード UTF-8 (BOMなし)。

§6.1 ライブラリ

依存ゼロ。手書き実装。これは原理主義です。

§8. 将来拡張 (Out of Scope, ただし議論用)

  • チェックサム: 末尾に大字 (零壱弐参肆伍陸漆捌玖拾佰仟萬) で mod-100 検査値2文字
  • 大字Base16版: もっと文字制限が厳しい場合用のフォールバック
  • PGP armor互換ラッパ: -----始める 猫乃の鍵----- / -----終わる 猫乃の鍵----- で囲む
  • 縦書きPDF出力: 内容証明テンプレに流し込んで即郵送可能なPDFを生成
  • OCRラウンドトリップ検証: 印刷→スキャン→OCR→復号が通るかを実機テスト
